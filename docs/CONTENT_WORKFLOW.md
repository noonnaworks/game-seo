# 콘텐츠 게시 품질 Gate

사이트 운영: 플레이노트 / NoonNa Works. 이 문서는 관리자를 위한 절차이며 사용자 화면에 가짜 검수 상태를 만들지 않습니다.

## 새 글을 만들기 전

1. 사용자의 질문을 한 문장으로 적습니다. 같은 게임의 기존 title·searchIntent·searchQuestions·본문을 먼저 확인합니다.
2. 같은 문제의 다른 표현이면 새 URL을 만들지 않고 기존 글에 예외·단계를 보완합니다.
3. 서로 다른 글이 같은 searchIntent나 정규화된 검색 질문을 사용하면 자동 검사가 실패합니다. 이 검사는 의미가 같은 모든 한국어 표현을 이해하지 못하므로 사람의 중복 의도 판단을 대체하지 않습니다.

## 게시 전 18단계

| 순서 | 확인 사항 | 남길 근거 |
| --- | --- | --- |
| 1 | 실제 검색 의도 | searchIntent와 독자의 질문 |
| 2 | 기존 글과 중복 여부 | 기존 글 목록 비교, 확장 또는 신규 결정 |
| 3 | 최신 공식 자료 검색 | 개발사·퍼블리셔 공지, 공식 FAQ·지원·Wiki 우선 |
| 4 | 자료 게시 날짜 | URL 날짜가 아닌 문서에 표시된 게시일 |
| 5 | 과거 자료와 충돌 | 변경된 내용과 충돌 문서 기록 |
| 6 | 최신 자료 우선 적용 | 최신 출처를 우선한 이유와 범위 |
| 7 | 실제 UI 용어 | 한국어 게임 화면 또는 공식 문구 |
| 8 | 플랫폼 차이 | PC·모바일·콘솔 및 서버 예외 |
| 9 | 불확실 정보 | 삭제하거나 reviewWarning으로 명확히 표시 |
| 10 | 원출처 | reviewSources와 본문 공식 자료 링크 |
| 11 | 원자료 이상의 가치 | 빠른 답, 순서, 예외, 체크리스트, 다음 행동 |
| 12 | 2차 팩트체크 | 핵심 주장별 다른 근거 대조와 검수자 확인 |
| 13 | 링크 | 자동 내부 링크 검사, 외부 출처 실제 확인 |
| 14 | 이미지 권리 | 촬영·허가·공식 이용 조건과 출처 |
| 15 | 모바일 | 360/520/760px에서 제목·답·목차·긴 용어·출처 넘침 확인 |
| 16 | build | npm run build 성공 |
| 17 | 자동 검사 | check.mjs, check-preview.mjs 성공 |
| 18 | 로컬 검수 | Desktop·Tablet·Mobile 키보드·화면 확인 |

어느 단계라도 미완료면 신규 게시·재게시 완료로 간주하지 않습니다. 자동 검사 통과는 콘텐츠 검수 완료가 아닙니다. 현재 기존 두 글은 원문 보존 요청에 따라 URL과 본문을 유지하며, 부분 검증 상태를 공개합니다. 이번 작업에서 자동 배포하거나 검수 완료로 승격하지 않습니다.

## 상태와 날짜

- `reviewed: true`는 실제 자료 대조를 수행했다는 뜻입니다. 게임 내 직접 플레이 또는 사람의 최종 승인이라는 뜻이 아닙니다.
- `verificationStatus: partially-verified`는 확인 범위와 미확인 범위를 함께 써야 합니다.
- `verificationStatus: verified`는 핵심 주장, 플랫폼·UI, 충돌 자료 및 품질표를 확인한 뒤 운영자가 명시적으로 설정합니다. 빌드가 자동 설정하지 않습니다.
- `reviewed: false` 또는 날짜가 없으면 ‘검토 기록 없음’으로 표시합니다.
- 검토일은 실제 대조 날짜만 기록합니다. 재검토만으로 `updated`, sitemap lastmod, Article dateModified를 변경하지 않습니다.
- 실제 본문 내용을 고치면 `updated`를 바꾸고, 의미 있는 변경만 changelog에 기록합니다.
- 커뮤니티 주장만 확인했으면 sourceType을 community 또는 mixed로 기록하고 공식 사실처럼 표현하지 않습니다.

| 친구와 같은 서버 | 2026년 공식 FAQ Q20~Q22, 10월 서버 공지, 과거 생존 안내의 공통 내용·예외 대조 | 현재 서버의 초대 제한, 플랫폼별 UI, 실제 계승·탈퇴 동작 직접 확인 | 일부 확인 |

2025년 FAQ의 서버 이동 제한 설명과 2026년 FAQ의 탈퇴·등록 설명이 다릅니다. 서버 이동은 최신 FAQ와 현재 시나리오의 계승 안내를 우선 확인합니다. 입문 글의 과거 용어는 원문 보존 요청 때문에 유지했고 제한을 상단에 표시했습니다. 실제 플레이 스크린샷이나 허위 확인 경력을 만들지 않았습니다.

개발 환경의 브라우저 접근 정책 때문에 실제 뷰포트 시각 검수는 완료하지 못했습니다. 소스 기반 overflow 위험 검사와 로컬 HTTP 검사는 수행했지만, 이 결과만으로 품질 Gate의 15·18단계를 통과 처리하지 않습니다.

## 사람이 준비할 자료

- 현재 한국어 UI의 ‘더 많은 서버’, ‘특별 초대 코드’, ‘강제 시나리오 탈퇴’ 위치와 플랫폼별 화면
- 현재 초보 기술·제작 해금 흐름, 과거 ‘밈’ 용어와의 대응
- 직접 촬영한 설명용 스크린샷과 버전·권리 정보
- Desktop/Tablet/760/520/360px 실제 화면 및 키보드 검수
- Cloudflare 배포 후 임의의 없는 URL의 실제 HTTP 404, GSC 인증 상태

허가된 스크린샷이 없으면 이미지 없이 게시합니다. 빈 placeholder와 다른 블로그·영상의 무단 캡처는 사용하지 않습니다.
